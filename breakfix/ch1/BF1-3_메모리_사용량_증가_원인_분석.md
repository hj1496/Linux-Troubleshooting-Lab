# BF 1-3. 메모리 사용량 증가 원인 분석

## 1. 개요

| 항목  | 내용                                                   |
| --- | ---------------------------------------------------- |
| 환경  | Rocky Linux 8.10 (`node1`)                           |
| 현상  | 메모리 사용량 증가                                           |
| 목표  | 메모리 점유 프로세스를 식별하고 실제 메모리 부족 여부 판단                    |
| 진단  | 프로세스 RSS, available 메모리, swap 및 `vmstat`의 `si/so` 비교 |

## 2. 문제 현상

- 메모리 사용량이 약 500 MiB로 증가했다.
- 특정 프로세스가 메모리를 점유하는지, 시스템에 메모리 부족이 발생했는지 확인이 필요했다.

## 3. 원인 분석

### ① 메모리 점유 프로세스 확인

```bash
ps -eo pid,user,comm,%mem,rss --sort=-%mem | head
ps aux --sort=-%mem | head
```

- PID 1661의 Python 프로세스가 약 360 MiB의 RSS를 사용했다.
- 실행 명령에는 약 350 MiB를 할당한다.

### ② 프로세스 실행 관계 추적

```bash
pstree -sp 1661
```

- `timeout → python3` 실행 관계를 확인했다.
- 메모리 사용량 증가의 직접적인 원인은 Python 프로세스의 메모리 할당이었다.

### ③ 메모리 부족 여부 판단

```bash
free -h
vmstat 1 5
```

| 확인 항목 | 당시 관찰 결과 |
|---|---|
| available 메모리 | 약 2.8 GiB |
| swap 사용량 | 0 |
| swap in/out (`si`, `so`) | 0 / 0 |

- 여유 메모리가 남아 있고 스왑 입출력이 발생하지 않았다.
- 메모리 점유량은 증가했지만, 실제 메모리 압박(memory pressure)이 발생한 상태는 아니었다.

## 4. 해결 과정

- 메모리를 점유하던 Python 프로세스를 종료했다.
- 메모리 상태를 다시 확인했다.

## 5. 결과

- 메모리 사용량 증가 원인을 PID 1661의 Python 프로세스로 특정했다.
- available 약 2.8 GiB, swap 사용량 0, `si/so=0`을 근거로 메모리 부족 상태가 아님을 확인했다.
- 원인 프로세스를 종료하고 사후 메모리 상태를 확인했다.
