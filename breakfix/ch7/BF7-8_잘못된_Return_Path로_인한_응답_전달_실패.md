# BF7-8 — 잘못된 Return Path로 인한 응답 전달 실패

## 1. 개요

| 항목 | 내용 |
|---|---|
| 환경 | Rocky Linux 8.10 / `bf8-client`–Router–`bf8-server` |
| 대상 | Server → Client `10.110.1.10`의 반환 경로 |
| 원인 | 잘못된 Next Hop을 가리키는 `/24` 정적 경로 |
| 진단 | Server의 `ip route` 및 `ip route get`으로 반환 경로 확인 |
```
[node1]

┌──────────────────────┐
│ bf8-client           │
│ 10.110.1.10          │
└──────────┬───────────┘
           │
           │ Request
           ▼
┌──────────────────────┐
│ Router               │
│                      │
│ Server 측 Gateway    │
│ 10.110.2.1           │
└──────────┬───────────┘
           │
           │ 10.110.2.0/24
           ▼
┌────────────────────────────┐
│ bf8-server                 │
│                            │
│ Return Route               │
│ 10.110.1.0/24              │
│ via 10.110.2.254 [X]       │
└────────────────────────────┘

[장애]
Server → Client 응답 경로 오류

[정상]
Server → 10.110.2.1 → Client
```
## 2. 문제 현상

Client와 Server 사이에 통신 장애가 발생했다. 특히 Server가 Client `10.110.1.10`으로 응답을 돌려보내는 경로를 조사했다.

## 3. 원인 분석

Server의 라우팅 테이블에서 확인된 경로:

```text
10.110.1.0/24 via 10.110.2.254 dev bf8-s
```

- `10.110.1.10`으로 가는 트래픽은 더 구체적인 `/24` 정적 경로가 우선 선택된다.
- 해당 경로의 Next Hop `10.110.2.254`는 잘못된 값이었다.
- 올바른 반환 경로의 Next Hop은 Router 측 `10.110.2.1`이다.

**원인:** Server의 잘못된 반환 경로가 Client로 향하는 응답을 다른 Next Hop으로 전송했다.

## 4. 해결 과정

당시 제시된 잘못된 정적 경로 삭제 명령:

```bash
ip -n bf8-server route del 10.110.1.0/24 via 10.110.2.254
```

이 조치로 목적지에 대한 잘못된 우선 경로를 제거하고 정상 반환 방향을 사용하도록 한다. 사후 `route get` 또는 Ping의 구체적인 출력은 기재하지 않는다.

## 5. 결과

- 잘못된 반환 Next Hop `10.110.2.254`를 원인으로 확인하고 경로 수정으로 실습을 마무리했다.
