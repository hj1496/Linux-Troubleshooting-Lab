# BF9-8. 공유 볼륨에 `:Z`를 중복 적용해 발생한 MCS Label 충돌

## 1. 개요

| 항목 | 내용 |
|---|---|
| 환경 | Rocky Linux 8.10 / Podman / SELinux Enforcing |
| 증상 | 두 번째 컨테이너 실행 후 첫 번째 컨테이너의 공유 파일 접근 실패 |
| 원인 | 같은 디렉터리를 `:Z`로 재레이블링해 첫 컨테이너와 MCS 범주 불일치 |
| 해결 | 두 컨테이너 모두 공유용 `:z` 옵션 사용 |

## 2. 문제 현상

컨테이너 A, B가 같은 호스트 디렉터리 `/srv/rh342-bf98`을 각각 마운트했다.

| 컨테이너 | 호스트 포트 | 관찰 결과 |
|---|---|---|
| A | `18098` | 단독 실행 시 정상, B 실행 후 접근 실패 |
| B | `18099` | 동일 디렉터리를 `:Z`로 마운트 |

컨테이너 A가 실행 중인데도 공유 콘텐츠 접근이 실패한 점이 핵심 증상이었다.

## 3. 원인 분석

- `:Z`는 한 컨테이너 전용 MCS 범주를 사용하도록 마운트 대상의 SELinux Label을 변경한다.
- B가 같은 호스트 디렉터리에 `:Z`를 적용하면서 디렉터리의 MCS 범주가 B에 맞게 바뀌었다.
- A의 프로세스 Label과 공유 디렉터리의 범주가 달라져 A의 접근이 거부됐다.

즉, 볼륨이 없어지거나 프로세스가 중지된 문제가 아니라 **공유 대상으로 설정한 디렉터리에 전용 Label 옵션을 적용한 구성 충돌**이었다.

## 4. 해결 과정

두 컨테이너를 재생성하면서 공유 디렉터리의 옵션을 `:Z`에서 `:z`로 변경했다.

```text
A: -p 127.0.0.1:18098:8080
B: -p 127.0.0.1:18099:8080
공통: -v /srv/rh342-bf98:/var/www/html:ro,z
```

`:z`는 여러 컨테이너에서 함께 사용할 수 있도록 공유용 SELinux Label을 적용한다.

## 5. 결과

- A의 `127.0.0.1:18098`에서 HTTP `200 OK` 확인.
- B의 `127.0.0.1:18099`에서 HTTP `200 OK` 확인.
