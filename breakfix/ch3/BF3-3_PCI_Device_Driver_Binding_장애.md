# 3-3. PCI Device / Driver Binding 장애

## 1. 개요

| 항목 | 내용 |
|---|---|
| 환경 | Rocky Linux 8.10 / VirtualBox |
| 대상 | PCI `0000:00:08.0` / `e1000` / `enp0s8` |
| 증상 | PCI 장치와 드라이버 모듈이 존재하지만 네트워크 인터페이스가 사라짐 |
| 원인 | PCI 장치와 `e1000` 드라이버의 바인딩 해제 |
| 진단 전략 | 장치 인식 → 모듈 로드 → 드라이버 바인딩 상태 순서로 확인 |

## 2. 문제 현상

```bash
ip -br link
```

기존에 존재하던 `enp0s8` 인터페이스가 보이지 않았다.

## 3. 원인 분석

**① PCI 장치 인식 확인**

```bash
lspci -k
```

- PCI `00:08.0`의 Intel 82540EM 네트워크 장치는 인식되었다.
- 해당 장치에 `Kernel modules: e1000`은 표시되었으나 `Kernel driver in use` 항목이 없었다.

**② 드라이버 모듈 로딩 확인**

```bash
lsmod | grep '^e1000'
modinfo e1000
```

- `e1000` 모듈은 로드된 상태였다.
- 따라서 드라이버 모듈이 없거나 미로드된 상황과 구분했다.

**③ PCI 장치와 드라이버 연결 확인**

```bash
ls /sys/bus/pci/drivers/e1000/
ls /sys/class/net/
```

- `e1000` 드라이버 디렉터리에 `0000:00:08.0`이 없었다.
- `/sys/class/net/`에도 `enp0s8`이 없었다.
- 커널 로그에서는 이 증상의 직접적인 원인을 확정할 만한 추가 오류를 확인하지 못했다.

**원인:** PCI 장치는 존재하지만 `e1000` 드라이버에 바인딩되지 않아 인터페이스가 생성되지 않았다.

## 4. 해결 과정

해당 PCI 장치를 `e1000` 드라이버에 다시 바인딩했다.

```bash
echo '0000:00:08.0' > /sys/bus/pci/drivers/e1000/bind
```

바인딩 상태와 인터페이스 생성 여부를 다시 확인했다.

```bash
lspci -k
ip -br link
ls /sys/bus/pci/drivers/e1000/
```

## 5. 결과

- PCI `00:08.0`이 `e1000` 드라이버에 다시 연결되었다.
- 누락되었던 `enp0s8` 인터페이스가 복구되었다.
